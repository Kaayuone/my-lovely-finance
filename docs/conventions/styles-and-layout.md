## PrimeVue + стили

- Компоненты PrimeVue импортируем поштучно: `import Button from 'primevue/button'`.
- Стилизация — утилитами **TailwindCSS**; для внутренних частей PrimeVue используем `:pt` (passthrough).
- Поля ввода оборачиваем в `FloatLabel` с `<label :for>`, связанным по `id`; обязательные помечаем `*`.

**Фокус при открытии `Dialog`.** PrimeVue фокусирует первый `[autofocus]` внутри дефолтного слота,
а если такого нет — кнопку-крестик, принудительно с кольцом фокуса (`focusVisible: true`). Заголовок,
переданный пропом `header`, в этом поиске не участвует. Поэтому у каждого `<Dialog>` должен быть явный
приёмник фокуса:

- есть осмысленная кнопка действия — вешаем на неё `autofocus`;
- кнопки действия нет (напр. полноэкранный пикер) — первой строкой слота ставим
  `<DialogFocusGuard />` (`components/DialogFocusGuard.vue`; переносится из My Lovely Car —
  `src/components/DialogFocusGuard.vue` — с первым таким диалогом).

`FormDrawer` — исключение: он рендерит слот `#container`, штатная кнопка закрытия PrimeVue там не
создаётся, фокусировать нечего. Сам `FormDrawer` переносится из My Lovely Car
(`src/components/FormDrawer.vue`) с первой формой.

**Цвета — только переключаемые роли, не числовая шкала `surface-*`.** Aura задаёт `surface-*`
одинаково направленно в обеих схемах (`surface-950` тёмный и в светлой теме), поэтому хардкод по этой
шкале ломает светлую тему. Допустимы только средние значения (`surface-400`/`500`), читаемые на обоих
фонах.

| Роль                                         | Утилита                                 | Источник                                                                                        |
| -------------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Фон страницы, полноэкранных пикеров, дровера | `bg-app`                                | `--app-bg`, `assets/main.css`                                                                   |
| Фон карточки-секции и шапки                  | `bg-card`                               | `--app-bg-card`                                                                                 |
| Разделители (`<hr>`), рамки                  | `text-line` / `border-line` / `bg-line` | `--app-border`                                                                                  |
| Фон поля ввода и триггеров, имитирующих поле | `bg-field`                              | `--p-form-field-background`                                                                     |
| Фон выключенного поля и таких же кнопок      | `bg-field-disabled`                     | `--p-form-field-disabled-background`                                                            |
| Рамка поля ввода и таких же триггеров        | `border-field-line`                     | `--p-form-field-border-color`                                                                   |
| Основной текст                               | `text-color`                            | `tailwindcss-primeui`                                                                           |
| Вторичный текст, подписи                     | `text-muted-color`                      | `tailwindcss-primeui`                                                                           |
| Выделенный элемент списка                    | `bg-highlight`                          | `tailwindcss-primeui`                                                                           |
| Акцент                                       | `text-primary` / `bg-primary`           | активный акцентный цвет; `text-primary` в светлой теме на ступень темнее (`--app-primary-text`) |
| Текст ошибки валидации                       | `text-invalid`                          | `--p-form-field-invalid-placeholder-color`                                                      |

Тёмная/светлая тема переключается классом `.dark-mode` на `<html>` (`darkModeSelector` в `main.ts`,
`@custom-variant dark` в `main.css`, `applyDarkMode` в `services/theme`); настройка живёт в
`settingsStore`. Акцент — `DEFAULT_ACCENT_COLOR` из `services/theme`: палитру `primary` собирает
`buildPrimaryRamp` в пресете `main.ts`. Точечно можно использовать вариант `dark:` (напр. разная
тень), но фоновые уровни задаём ролями, а не парами `dark:`.

```vue
<script setup lang="ts">
import Drawer from 'primevue/drawer';
import { computed } from 'vue';

const { modelValue } = defineProps<{ modelValue: boolean }>();
const emit = defineEmits<{ 'update:model-value': [value: boolean] }>();

const visible = computed({
  get: () => modelValue,
  set: value => emit('update:model-value', value),
});
</script>
```

## Адаптив

Новый UI сразу верстаем адаптивно — не «потом причешем». Базовый (без префикса) стиль обязан
корректно работать на **320px**, дальше прогрессивно расширяемся через `w360:`, `w400:`, `w600:`
и `w720:` (объявлены в `assets/main.css`). Других брейкпоинтов не добавляем: планшеты — только в
книжной, и им хватает одного тира `w600:` с колонкой контента, а 10" — тот же интерфейс, крупнее
через корневой шрифт (опыт My Lovely Car). Ширину в JS не определяем (`matchMedia`,
`window.innerWidth` — нет).

| Тир     | Префикс   | Диапазон | Устройства                                                    |
| ------- | --------- | -------- | ------------------------------------------------------------- |
| База    | —         | 320–360  | телефоны                                                      |
| `w360:` | ≥ 22.5rem | 360–400  | телефоны                                                      |
| `w400:` | ≥ 25rem   | 400–600  | крупные телефоны                                              |
| `w600:` | ≥ 37.5rem | 600–720  | 7–8" планшеты в книжной (≈ 600), раскрытые складные           |
| `w720:` | ≥ 45rem   | 720+     | 10–11" планшеты в книжной (720–800): интерфейс крупнее на 25% |

**Сначала флюидное решение, потом тировое.** `min-w-0`, `flex-1`/`basis-0`, `shrink-0`,
`flex-wrap`, `line-clamp-*`, `max-w-[min(...,calc(100vw-2rem))]` работают на всех ширинах сразу;
`w360:`/`w400:` — только когда надо физически уменьшить размер (иконки, отступы, кегль), `w600:` —
когда планшету нужна другая геометрия, а не просто больше места. `w720:` в компонентах не
используем: он только масштабирует весь интерфейс, см. ниже.

**10" — тот же интерфейс, на 25% крупнее.** От `w720:` у `<html>` `font-size: 125%`, и всё, что
задано в rem, растёт само: утилиты Tailwind, токены PrimeVue, колонка 40rem. Медиазапросы читают rem
от начальных 16px, тиры не сдвигаются. Поэтому размеры в вёрстке — только в rem и утилитами
Tailwind; px на 10" не растёт. Иконки Lucide с `:size` пересчитаны в rem в `assets/main.css` — по
строке на значение; новый `:size` добавляет туда свою строку.

**Планшет — колонка, а не новая раскладка.** Контент страницы не шире 40rem (`--container-column`)
и стоит по центру. Шапка и нижнее меню тянутся на весь экран, их содержимое стоит по колонке;
закреплённое у края — FAB, нижние панели — у края колонки, а не экрана. `FormDrawer` и полноэкранные
пикеры остаются на весь экран, как в нативных Android-приложениях, — по колонке стоит их содержимое.
Две колонки — только у сводок из парных карточек (`card-pairs`, см. ниже). Разницу между 7" (600) и
10" (800) закрывают флюидная вёрстка и масштаб 10".

- **Колонку держат отступы, а не ширина контейнера.** Прокручиваемая область, шапка и шторка
  остаются во всю ширину — свайп по полю тоже прокручивает, — а телефонный отступ меняется на
  колоночный: `px-4` → `px-column-4`, `right-4` → `right-column-4`, `left-4` → `left-column-4`
  (`assets/main.css`). Колоночный отступ — телефонный плюс `--column-gutter`, расстояние от края
  экрана до колонки; на телефоне оно 0, и вёрстка не меняется. `max-w-*` + `mx-auto` на контейнере
  скролла не годится: поля по бокам перестают прокручивать.
- **Нижняя панель сама становится колонкой**: `max-w-column mx-auto` на панели, внутри — телефонные
  отступы. Полноэкранные `FormDrawer`, шторки с `#container` и пикеры держат колонку отступами.
- **Пары карточек — `card-pairs`**: от `w600:` две колонки, нечётная последняя карточка — на всю
  строку. В контейнере лежат только парные карточки; ведущая карточка, пояснения и списки стоят вне
  его, иначе пары собьются. Утилита переносится из `src/assets/main.css` My Lovely Car с первой
  сводкой.

- **`min-w-0` на растущей колонке** — самая частая правка. Flex-элемент по умолчанию имеет
  `min-width: auto` и не сжимается ниже контента, поэтому `grow` рядом с `min-w-fit` выдавливает
  соседа за экран, а уже написанный `line-clamp-*` не срабатывает.
- **Поля PrimeVue с `fluid`** в общем `flex`-ряду разрешают `width: 100%` относительно
  неопределённого родителя и откатываются на интринсик-ширину `<input>` (~180px). Два таких поля
  в ряду не влезают в шторку (288px на 320px-экране) — нужен `min-w-0 flex-1` на каждом.
- **Модалки** — `w-full max-w-[min(<желаемая>,calc(100vw-2rem))]`, иначе на 320px они шире экрана.
- **Заголовки окон** — общая шкала с шапкой: обычный `<h1>/<h2>` наследует `body` сам (preflight
  сбрасывает размер), а `.p-dialog-title` задаёт свой токен, поэтому ему шкалу повторяем явно
  (`w400:text-base text-sm`).
- **Фиксированная высота панелей** (`AppMenu` → `h-14.25 w360:h-16.25`, `HeaderShell` → `h-16`)
  держит `top-*`/`bottom-*` у `<main>` в `DefaultLayout` валидными на всех тирах — при смене
  вертикальных метрик правим оба места.
- **Автотестов на вёрстку нет**, кроме E2E-проверки, что стартовая страница на 320px не
  прокручивается по горизонтали (`e2e/app.spec.ts`). Проверка ручная: 320 / 360 / 400 / 430 в
  DevTools, для планшета — 600×960 и 800×1280 (720 — нижняя граница 10"), альбомные 960 и 1280 —
  только на то, что ничего не ломается; и прогон на реальном Android через `npm run dev:host`
  (эмуляция не воспроизводит метрики шрифтов WebView).
  Ломается всё только на реальных русских строках — длинные названия счетов, крупные суммы,
  «12 мая – 18 мая».

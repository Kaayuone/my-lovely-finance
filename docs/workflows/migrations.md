# Миграции

> **Статус:** действует
>
> **Сверен:** 12 ноября 2026 — миграция v1 в `definitions.ts`, `runner.ts`, `runner.test.ts`, снимок `migrationSql.test.ts` и харнесс `sqliteTestDatabase.ts`; схема БД 1; деньги и даты по ADR-0005
>
> **Пересмотр:** при изменении раннера миграций или появлении бэкапа

Схема SQLite строится только миграциями
([ADR-0002](../adr/0002-schema-built-by-migrations-only-every-write-through-the-transaction-queue.md)):
новая установка проходит все шаги с версии 0, существующая база — только недостающие. Устройство
слоя — [`data-layer.md`](../architecture/data-layer.md).

## Шаги

1. **Новая запись в конец `MIGRATIONS`** в
   [`definitions.ts`](../../src/database/migrations/definitions.ts): `version` на единицу больше
   предыдущей, в `statements` — SQL шага по одному оператору на строку массива. В комментарии над
   записью — почему шаг нужен. Таблицы, индексы и встроенные строки — всё здесь, отдельной «полной
   схемы» нет.
2. **Форма таблиц:** столбцы snake_case, внешние ключи с явным `ON DELETE`, ограничения через
   `CHECK`. Деньги и даты — по
   [ADR-0005](../adr/0005-money-as-signed-minor-units-moment-with-offset-computed-balance.md):
   целые минимальные единицы валюты со знаком, момент в миллисекундах UTC и смещение в минутах.
3. **Формат SQL для нативного плагина.** `getStatementsArray` в `UtilsSQLite.java` режет текст
   миграции по `;\n`, склеивает обратно только `END` на отдельной строке и вырезает всё от `--`
   до конца строки. Поэтому в теле триггера ровно один оператор, `END` стоит на своей строке,
   а `--` нет нигде в SQL — ни в комментариях, ни в литералах. Комментарии пишутся в TS над
   записью миграции. Миграция v1 в таком формате проверена на телефоне 12 ноября 2026.
4. **Снимок SQL.** `migrations/__tests__/migrationSql.test.ts` сверяет SQL всех шагов со снимком
   `migrations/__tests__/__snapshots__/migrations.sql`. Новая миграция дописывает туда свою версию:
   `npx vitest run src/database/migrations/__tests__/migrationSql.test.ts -u` — в diff снимка
   меняется только она. Снимок коммитится вместе с миграцией.
5. **Тесты.** Поведение схемы — ограничения, каскады, перенос данных — проверяется интеграционным
   тестом на `sqliteTestDatabase.ts`: `initializeTestDatabase()` поднимает базу всеми шагами, а
   `initializeTestDatabase(MIGRATIONS.slice(0, n))` — базу старой версии, на которой проверяют
   переход.
6. **Документация** — по [`docs-update.md`](docs-update.md): «Модель» в
   [`data-layer.md`](../architecture/data-layer.md) и профильный документ модуля.

## Правила

- Выпущенный шаг не редактируется. Ошибку исправляет следующий шаг.
- Снимок SQL меняется только у невыпущенной версии — той, что появилась после последнего релиза и
  чьё изменение ещё в разделе «Не выпущено» `CHANGELOG.md`, — или у новой.
- Шаг выполняется одной транзакцией вместе с новой версией: внутри все операторы идут с
  `transaction = false` — раннер передаёт этот флаг сам.
- Шаг, который пересобирает таблицу (ограничения `ALTER TABLE` в SQLite), делает это внутри своей
  транзакции: новая таблица, копия данных, удаление старой, переименование, индексы заново.

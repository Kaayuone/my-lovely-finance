## Решение вместо факта

Если изменение — выбор между вариантами, у которого есть цена, оно идёт в [`adr/`](../adr/), а не в
архитектурный документ. Архитектурный документ отвечает «как сейчас устроено», ADR — «почему так, а
не иначе, и что мы за это заплатили». ADR не переписывают: новое решение — новый файл со строкой
«Изменяет: ADR-XXXX».

## Жизненный цикл документа

- **План выполнен** → дописать раздел «Итог» (что вышло, в какой версии, чем отличается от плана,
  где живёт текущее поведение) и перенести файл из `plans/active/` в `plans/completed/`.
- **Документ описывает модель, которой больше нет** → статус `архив`, поле «Чем заменён», файл
  переезжает в `archive/`.
- **Документ заменён другим** → статус `заменён (X.md)`, ссылка на замену.
- **Черновик продукта утверждён владельцем** → метки «[рекомендация]» снимаются с утверждённого,
  статус — `действует`.

Каталоги `plans/` и `archive/` заводятся, когда в них появится первый документ.

## Сверка

Поле «Сверен» в статус-блоке — не дата последней правки файла, а дата, когда документ читали рядом
с кодом. Меняете документ по существу — обновите дату и перечислите, что именно сверяли. Поле
хранит одну сверку — последнюю; история — в `git log -p`.

Механику проверяет `npm run check:docs`: битые ссылки и якоря, состав статус-блока (первый абзац
после заголовка), поле «Сверен» без истории («ранее …»), план в `completed/` без «Итога», версия
приложения в «Сверен» против `package.json` и версия схемы БД против `MIGRATIONS`. Смысл проверка не
видит — за него отвечает автор изменения.

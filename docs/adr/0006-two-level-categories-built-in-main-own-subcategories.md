# ADR-0006. Категории — два уровня: встроенные основные и подкатегории, свои — только подкатегории

- **Статус:** принято
- **Дата:** 11 ноября 2026
- **Этап:** этап 1, версия «для себя»
- **Связанные документы:** [`product/mvp.md`](../product/mvp.md#монетизация),
  [ADR-0005](0005-money-as-signed-minor-units-moment-with-offset-computed-balance.md),
  [`data-layer.md`](../architecture/data-layer.md)

## Контекст

Владелец хочет основные категории с подкатегориями: подкатегория — частный случай основной, чтобы
траты можно было смотреть и крупно, и подробно. Набор основных — настолько широкий, чтобы своя
основная категория никому не понадобилась. Названия — короткие: длинные не помещаются в строку и
хуже читаются в отчётах. Скрыть ненужную встроенную категорию можно бесплатно, свои подкатегории —
платная функция ([`mvp.md`](../product/mvp.md#монетизация)). Позже приложение выйдет с английским
листингом, и встроенные названия придётся показывать на втором языке.

## Рассмотренные варианты

**Плоский список.** Просто, но либо категорий слишком много для выбора, либо они слишком крупные для
анализа. Отвергнуто.

**Дерево любой глубины.** Гибко, но выбор категории становится навигацией по уровням, отчёты —
рекурсивными запросами, а владелец сам ограничил глубину двумя уровнями. Отвергнуто.

**Два уровня, свои основные разрешены.** Свои основные размывают отчёты по основным категориям и
обесценивают широкий встроенный набор. Отвергнуто.

**Два уровня, основные только встроенные, свои — только подкатегории.** Отчёт по основным
категориям одинаково устроен у всех, подробность — в подкатегориях. Принято.

## Решение

- Категория — основная (`parent_id` пуст) или подкатегория основной; подкатегория подкатегории
  невозможна, это проверяет база, а не только код.
- Два набора: расходы и доходы (`kind`). Подкатегория — того же набора, что её основная.
- Все основные категории встроенные. Встроенные подкатегории приходят с миграциями; свои
  подкатегории человек создаёт внутри любой основной.
- У встроенной категории есть постоянный код (`food`, `food.fastfood`): на него ссылаются миграции,
  правила и шаблоны разбора, а когда появится второй язык, по нему же берётся название для показа.
  У своей подкатегории кода нет.
- Встроенную категорию нельзя удалить или переименовать, но можно скрыть: она пропадает из выбора,
  а операции и отчёты остаются.
- Операция может ссылаться и на основную категорию, без подкатегории.
- Своя подкатегория удаляется вместе с переносом её операций в основную — одной транзакцией.
- Названия уникальны среди основных категорий одного набора и среди подкатегорий одной основной.
  Одно название под разными основными допустимо, если смысл разный («Аренда» в «Жилье» и в
  «Транспорте»); встроенные подкатегории подобраны без смысловых повторов — одна трата не должна
  одинаково подходить в две. Названия встроенных — короткие, около 20 символов и меньше.
- Встроенная подкатегория «Финансы → Комиссии» — категория комиссии перевода по умолчанию
  (ADR-0005).

## Последствия

- Отчёт по основным категориям — группировка по основной категории самой операции или её родителя;
  рекурсии нет.
- Изменение встроенного набора после выпуска — новый шаг миграции, который находит категории по коду.
- Пока пейвола нет, создание своих подкатегорий доступно всем; ограничение добавит задача пейвола.
- Если когда-нибудь разрешат свои основные категории, отчёты по основным перестанут быть одинаковыми
  у всех пользователей — это затронет готовые правила и шаблоны, которые ссылаются на коды.
